# App Store metadata

The App Store Connect texts, kept in the project. Nothing is uploaded
automatically — open the file, copy the contents, paste it into the matching
field in App Store Connect.

The folders are named after the fastlane convention (`cs`, `en-US`, `en-GB`), so
if you ever decide to move to `fastlane deliver`, renaming `AppStore/` to
`fastlane/metadata/` is all it takes.

## Where everything goes

App Store Connect → **Apps → Chess → iOS App → 1.0 Prepare for Submission**
(the version in `MARKETING_VERSION` — keep the two in step). There is a language
switch at the top — every field is filled in separately for each language.

| Field in App Store Connect | File | Limit | Currently |
|---|---|---|---|
| App Name | `<language>/name.txt` | 30 characters | 26 / 28 / 28 |
| Subtitle | `<language>/subtitle.txt` | 30 characters | 26 / 29 / 26 |
| Promotional Text | `<language>/promotional_text.txt` | 170 characters | 155 / 160 / 160 |
| Description | `<language>/description.txt` | 4000 characters | 3268 / 3254 / 3257 |
| Keywords | `<language>/keywords.txt` | 100 characters | 99 / 96 / 96 |
| What's New in This Version | `<language>/release_notes.txt` | 4000 characters | 876 / 820 / 822 |
| App Preview and Screenshots | generated by the script, see [screenshots.md](screenshots.md) | 1–10 images | 8 + video |

(The three numbers are `cs` / `en-US` / `en-GB`, in that order.)

Alternative names, subtitles and keyword sets, the reasoning behind the ones in
use, and what the competition looks like are in
[alternatives.md](alternatives.md).

Checking it. The limits are the easy half — the three checks after them are the
ones that catch real mistakes: a word paid for twice across two indexed fields, a
stray space in the keyword list, and a paragraph left wrapped at 80 columns.

```bash
python3 - <<'PY'
import os,re
lim={'name.txt':30,'subtitle.txt':30,'keywords.txt':100,
     'promotional_text.txt':170,'description.txt':4000,'release_notes.txt':4000}
bad=0
for loc in ('cs','en-US','en-GB'):
    d=lambda f:open(os.path.join('AppStore',loc,f),encoding='utf-8').read().rstrip('\n')
    for f,m in lim.items():
        n=len(d(f)); bad+=n>m
        print(f'{loc:6}{f:22}{n:5}/{m}', 'OK' if n<=m else 'OVER!')
    # a word in two indexed fields is paid for twice and indexed once
    t=lambda f:set(re.findall(r'[\wÀ-ſ]+', d(f).lower()))
    for a,b in (('name.txt','subtitle.txt'),('name.txt','keywords.txt'),
                ('subtitle.txt','keywords.txt')):
        ov=t(a)&t(b); bad+=bool(ov)
        if ov: print(f'{loc:6}DUPLICATED {a} x {b}: {sorted(ov)}')
    # a space after a comma silently costs one of the 100 characters
    if ', ' in d('keywords.txt'): bad+=1; print(f'{loc:6}KEYWORDS: space after comma')
    # App Store Connect keeps newlines - a paragraph has to be a single line
    L=d('description.txt').split('\n')
    for i,l in enumerate(L[:-1]):
        if (l.strip() and L[i+1].strip() and not l.isupper() and not l.startswith(chr(8226))
                and not L[i+1].startswith(chr(8226))
                and not l.rstrip().endswith(('.','!','?',':','…'))):
            bad+=1; print(f'{loc:6}DESCRIPTION line {i+1} wrapped mid-paragraph')
print('ALL CLEAN' if not bad else f'{bad} problem(s)')
PY
```

Run it from the repository root, not from this directory.

## Which localisations to create, and why three

Keywords never combine across languages — each localisation is its own search
index — but **most storefronts index two of them**, so a second language is free
extra keyword space in the same country rather than a different market.

| Storefront | Indexes | What that buys |
|---|---|---|
| United States | English (U.S.) + Spanish (Mexico) | `es-MX` would double the US pool |
| Czechia | **Czech + English (U.K.)** | `en-GB` doubles the Czech pool |
| United Kingdom, Ireland, Australia, New Zealand | English (U.K.) | `en-GB` is the primary there |

So the three folders here are:

- **`en-US`** — primary language of the record, and what most English storefronts
  read.
- **`cs`** — primary in Czechia, and the one worth the most effort per hour:
  below Chess.com the whole Czech chess market is in the hundreds of ratings
  (see [alternatives.md](alternatives.md)).
- **`en-GB`** — primary in the UK/Ireland/Australia/New Zealand *and* the second
  index in Czechia. The same description as `en-US` with British spelling, and a
  subtitle that trades *computer* for *One or*, which is all the vocabulary gap
  chess leaves: unlike solitaire/patience, the game is called the same thing
  everywhere.

`es-MX` is the obvious next one (it would double the US keyword pool for the cost
of a translation), and it is *not* included here: the app's interface is English
and Czech only, so a Spanish-speaking visitor would arrive at an English app.
That is allowed, and plenty of apps do it, but it trades conversion for reach.
Worth trying once there is enough traffic to measure the trade rather than guess
at it.

## Notes on the individual fields

- **App Name** — has to be globally unique, and it is the single strongest
  ranking signal. Plain "Chess" belongs to Optime Software (205 787 ratings),
  hence `Chess Offline: Play & Review`: it carries *chess*, *offline*, *play* and
  *review* while still reading like a title. On the home screen the app stays
  just "Chess" / "Šachy" (`INFOPLIST_KEY_CFBundleDisplayName` and
  `InfoPlist.xcstrings`), which Apple does not mind — the home screen name only
  must not differ in *meaning*. That constraint is why the Czech store name leads
  with *Šachy*.
- **Subtitle** — the second strongest signal and the line people actually read in
  search results. It adds the terms the name could not fit (*two players*,
  *computer*, *no ads*) rather than repeating it. **No price in it**, in any
  language: guideline 2.3.7 covers the name and the subtitle alike, and
  *zdarma* / *free* is the wording that gets metadata rejected. "No ads" /
  "bez reklam" is not a price and is fine.
- **Keywords** — separate with commas and **no spaces** (a space counts towards
  the limit). Do not repeat words already in the name or subtitle, Apple indexes
  those separately; that is why *chess*, *offline*, *play*, *review*, *two*,
  *players* and *ads* are missing from the English lists. Do not name a
  competitor's app or engine — *lichess*, *chesscom*, *stockfish* and *magnus*
  are all somebody else's, and grounds for rejection.
- **Description** — write each paragraph as **one long line**. App Store Connect
  keeps newlines exactly as pasted, so a paragraph wrapped at 80 columns in the
  editor comes out ragged on the device while every other paragraph reflows
  around it. Note also that on iOS the description is **not indexed for search**
  — it is a conversion field only, so keywords in it buy nothing and the first
  three lines (all most people ever see) are what the effort belongs in.
- **Promotional Text** — the only field that can be changed without a new build
  and without review. Useful for seasonal or topical messages. Like the
  description, it is not indexed for search.
- **What's New** — App Store Connect usually does not offer this field for a
  first release. `release_notes.txt` is therefore written as an introduction to
  1.0 rather than as a changelog: paste it if Connect asks for it, skip it if it
  does not, and from 1.0.1 on replace it with the changes in *that* version,
  derived from the commits since the previous one. Check `MARKETING_VERSION` in
  the project first, so the notes describe the version actually being uploaded.

## Settings that are not filled in with text

**App Information** (shared across all languages):

- Primary Category: **Games → Board**
- Secondary Category: **Games → Strategy** — which is where Chess.com, Vintolo
  and Vinta Games all put theirs. Games → Education is the other candidate and
  would be wrong: the nine-chapter guide is a feature of a game, not a course,
  and the Education charts are a harder room with a worse-fitting audience.
- Content Rights: **contains third-party content** — the Staunton piece vectors
  are Cburnett's, used under the BSD licence (see
  [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) and the app's *Settings →
  Credits*), so the honest answer is that it does contain third-party content and
  the rights to use it are in hand. Everything else — engine, review, guide,
  synthesized sounds — is the project's own.
- **Gambling: No.** No real money, no wagering, nothing to buy.

`LSApplicationCategoryType` is *not* set in this project. It has no effect on the
App Store listing — it is the Mac App Store key — so nothing here depends on it;
if you want the bundle to say the same thing about itself that the listing does,
add `INFOPLIST_KEY_LSApplicationCategoryType = public.app-category.board-games`
to the app target.

**Age Rating: 4+.** Everything in the questionnaire is None. Chess has no
violence, no chat, no links out, no contests, no loot boxes, no unrestricted web
access and no user-generated content, and — unlike much of the category — no
advertising, which is what the apps carrying 12+ and 17+ in this genre are
almost all carrying it for. Watch out for *Chance-Based Activities* → **None**:
chess is a game of pure skill, nothing is wagered and nothing pays out.

**Pricing and Availability:** Free, all countries.

**App Privacy:** click *Get Started* → **"No, we do not collect data from this
app"**. The game has no networking code, no third-party SDKs, and stores
everything in UserDefaults on the device (declared in
`chess/PrivacyInfo.xcprivacy`, reason CA92.1). A **privacy policy URL is still
mandatory** — the text is ready in [privacy-policy/](privacy-policy/), it just
needs hosting somewhere (GitHub Pages, a gist, your own site) and the URL pasted
into the *Privacy Policy URL* field.

**Support URL:** a mandatory field. The project's GitHub page or a simple page
with an e-mail address will do.

**Marketing URL:** optional, feel free to leave it empty.

**Encryption:** `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` is already set
in the project, so the export compliance question never appears when the build is
uploaded.

**App Review Information** → the note for the reviewer is in
[review-notes.txt](review-notes.txt). The game needs neither an account nor a
demo login — leave *Sign-in required* switched off.

**In-App Events** (App Store Connect → the app → *Events*): not filled in, and
the largest piece of indexed text still on the table. The event **name (30)** and
**short description (50)** are both indexed for search, and up to ten events can
be live at once — 800 characters against the 160 that the name, subtitle and
keyword field come to together. Nothing here is required to ship, and this app
has no recurring event to hang one on, so it belongs to a later version if at all.

## Release procedure

1. Xcode → Signing & Capabilities, check the team `K6GM85X5D7` and the bundle ID
   `cz.rob.chess`.
2. App Store Connect → **Apps → +** → new record, bundle ID `cz.rob.chess`,
   primary language **English (U.S.)** — the fallback for every storefront
   without its own localisation — SKU e.g. `chess-001`. For a later version it is
   **+ Version or Platform** instead, and the localisations are inherited.
3. Add the other two localisations: App Information → the language switch, top
   right → **Czech** and **English (U.K.)**.
4. Fill in the texts from this directory in every language. From 1.0.1 on,
   `release_notes.txt` is the one field that has to change for every version; the
   rest carry over from the previous one and only need touching when they are
   actually out of date.
5. Re-upload the media only if the app looks different from the last version.
   The screenshots and App Previews are not in the repo — build them with
   `Tools/appstore_media.sh` and upload them, see
   [screenshots.md](screenshots.md) for details. The iPhone slot this listing
   uses is **6.5"**, not 6.9". `en-GB` has no media of its own; upload the
   `en-US` set into it.
6. Bump **`CURRENT_PROJECT_VERSION`** in the project (all configurations — it is
   the build number, `CFBundleVersion`) and set `MARKETING_VERSION` to the
   version being released. App Store Connect only requires the build number to be
   unique *within* a version string, but raise it on every upload anyway,
   rejected ones included: the first re-upload of a version has to bump it, and
   every tool that reads build numbers assumes they only ever go up.
7. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
8. Wait for the build to process (10–60 min), then select it in the *Build*
   section.
9. Fill in App Privacy, Age Rating, Pricing.
10. **Add for Review** → *Submit*.
